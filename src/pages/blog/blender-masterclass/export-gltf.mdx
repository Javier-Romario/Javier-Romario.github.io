## What glTF carries

```text
.geometry   vertices, normals, UVs, triangle indices
.materials  PBR: base color, normal, roughness, metallic
.textures   embedded or external images
.animation  bones, weights, keyframes (skeletal or morph)
```

STL = geometry only. glTF = the whole asset. That's why games and the web use glTF.

## Export settings that matter

```text
File → Export → glTF 2.0 (.glb)

✓ Apply Modifiers     ← bake your stack, same as STL
✓ +Y Up               ← glTF convention (three.js expects it)
✓ Embed Textures      ← one self-contained file
✓ Compress            ← Draco or Meshopt: 10× smaller, decoded on load
```

<div class="poke">Toggle the settings and watch the export contract change. Compress = smaller file,
+Z up = Blender's native axis (fix it here, not in code later).</div>

## The .glb vs .gltf question

- **`.glb`** — binary, one file, everything embedded. Use this for the web.
- **`.gltf`** — JSON + separate `.bin`/texture files. Easier to hand-edit, messier to host.

For a react-three-fiber site, `.glb` is the answer: one request, drop it in `/public`.
