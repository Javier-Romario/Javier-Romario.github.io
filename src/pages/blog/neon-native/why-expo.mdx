## What Expo gives you

- **Expo Go** — an app on your phone that runs your code instantly over Wi-Fi. No Xcode, no Android Studio, no compile.
- **Dev builds** — a custom app with your native modules baked in (for when Expo Go isn't enough).
- **expo-router** — file-based navigation (step 09).
- **EAS** — Expo Application Services: cloud builds, submissions, OTA updates.
- **A vetted library ecosystem** — camera, location, notifications, secure store, all tested to work together.

<Takeaway math="Expo = React Native − the yak-shave" note="Same RN under the hood. Expo adds toolchain, modules, and cloud services." />

## Expo Go vs dev build

| | Expo Go | Dev build |
|---|---|---|
| Setup | install app, scan QR | `eas build` once |
| Native modules | only Expo SDK ones | any, including custom |
| Rebuild needed | never | when native deps change |
| Good for | learning, quick demos | real apps |

Start with **Expo Go**. The moment you add a native module that isn't in the Expo SDK, you
graduate to a **dev build**.

<Pitfall title="Managed workflow ≠ no native code">
  "Managed" doesn't mean "you can't touch native". It means Expo manages the native project
  for you. You can still <code>expo prebuild</code> to generate the iOS/Android folders and
  write your own Swift/Kotlin. You just don't have to.
</Pitfall>

## The trade-off

- **Pro:** speed to first app, one config file, cloud builds, OTA updates.
- **Con:** you're in Expo's ecosystem; some bleeding-edge native libs need a custom dev build.

For 95% of apps — and 100% of this guide — Expo is strictly the right call.
