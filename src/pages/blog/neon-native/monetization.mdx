## The three models

| Model | How it works | Complexity | Best for |
|---|---|---|---|
| Paid app | one-time price in the store | low | niche tools, premium |
| Ads | ad SDK pays per impression | low | free, high-engagement |
| IAP | subscriptions / consumables | high | most consumer apps |

## IAP: the basics

Apple and Google both take a cut (15–30%) of IAP and require you to use **their** payment
systems for digital goods (not physical goods, not services — those use Stripe).

- **Subscription** — recurring (monthly/yearly), needs a free trial and a cancel path.
- **Consumable** — buy repeatedly (coins, gems).
- **Non-consumable** — buy once (unlock pro, remove ads).

## Use RevenueCat

Store IAP APIs are wildly different (StoreKit vs Play Billing) and the edge cases (restore
purchases, refunds, sandbox testing) are painful. **RevenueCat** wraps both in one API:

```bash
npx expo install react-native-purchases
```

```tsx
import Purchases from 'react-native-purchases';

// init once, with your RevenueCat API keys
Purchases.configure({ apiKey: 'appl_...' });

// fetch what's for sale
const offerings = await Purchases.getOfferings();
const pkg = offerings.current?.availablePackages[0];

// buy
const { customerInfo } = await Purchases.purchasePackage(pkg);
const isPro = customerInfo.entitlements.active['pro'] !== undefined;

// restore on a new device
await Purchases.restorePurchases();
```

The `entitlements` object is the thing that matters: "is this user Pro?" — read it everywhere
you gate features.

## The paywall pattern

Gate premium features behind a paywall screen. Check entitlement, show paywall if not Pro:

```tsx
function ProFeature({ children }) {
  const isPro = useProStatus();
  if (!isPro) return <Paywall />;
  return children;
}
```

Free trial → value demo → paywall → purchase → unlock. In that order.

## Ads

If you go the ads route, use **react-native-google-mobile-ads** (AdMob). Start with banners
and interstitials, respect frequency caps, and never show an ad during a user's first 30
seconds — you'll tank retention.

<Pitfall title="IAP in Expo Go doesn't work">
  In-app purchases require a real build (dev build or store build) with the proper signing and
  bundle ID. Test against RevenueCat's **sandbox** environment. Also: the App Store rejects
  apps whose IAP flow is broken or whose paywall hides the "restore purchases" button.
</Pitfall>
